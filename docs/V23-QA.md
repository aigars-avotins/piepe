## Final motion review

The selected `review-animations`, `animate` and `animation-performance` references were reread from [Emil Kowalski's skills at `a81dbca`](https://github.com/emilkowalski/skills/tree/a81dbca07f2217b7103e510c0f13f8d5b017afc9/skills), including the review standards. They were used for review, construction choices and diagnosis respectively; no skill installer or runtime package was executed. The project's [curated cinematic exceptions](V22_MOTION_SKILLS_REVIEW.md) preserve deliberate film/shot timing and the existing GSAP architecture.

| Before | After | Why |
| --- | --- | --- |
| Camera scrub had to stop inside a narrow eligibility interval | Broad native sticky plateaus; activation independent of scrub idleness in `useForestMotion.ts:59` | Ordinary wheel/touch input reaches moving full-frame scenes without precision stopping |
| Environmental clips inherited session completion | Per-visit lifecycle in `EnvironmentalFilm.tsx:14`; one decoder and actual end-frame replay carrier | Every return moves; leaving and backgrounding release/pause resources |
| Cleanup restored the crop transition before committing the final observation crop | Commit once with transitions suppressed for two paints in `usePhotoHandoff.ts:78` | The recorded fungus settles once instead of moving again |
| Independent native clocks could distort or strand the nested photo camera | One existing GSAP clock writes exact aperture/inverse-image/shade transforms together (`usePhotoHandoff.ts:59`) | Actual source geometry stays consistent; preparation and mid-shot Escape remain interruptible |
| A hidden paused opening could lose its presented-frame callback | Stage matching decoded frame zero; register before/after source assignment; retain the final decoder through docking (`MotionClip.tsx:83`) | Playback readiness follows an actual presented frame, preserving the forest plane |

**Performance:** the photo clock runs on the main thread; transform/opacity writes do not make GSAP a compositor-thread animation. It avoids per-frame React state updates, animated layout dimensions, inherited animation variables and live-video pixel readback. Existing observation crop/SVG drawing transitions and the small three-cycle hint still involve paint; no whole-site composite-only or guaranteed physical-device frame-rate claim is made. The one-second spatial shot and six-second films follow the approved cinematic timing exception. Recorded geometry, actual moving pixels and the candid mobile measurements complement code inspection.

## Limits and publication

Native macOS WebKit means the Playwright WebKit engine/codecs on the macOS runner with desktop and phone contexts. It is not a physical iPhone or the Safari application. The local Chromium recordings are browser emulation, not handset measurements. Physical iPhone/Safari-app testing and owner-only Search Console indexing status cannot be claimed here.

The source environmental films are not perfectly cyclic camera paths. Their short end-frame bridge/forward dissolve is intentional; new media generation is not required for the activation/replay fix. Portrait footage necessarily excludes some horizontal field of view; [the asset brief](V23-ASSET-BRIEF.md) supplies genuine first/last source references and optional future portrait/scientific-image requirements. No new AI footage or 2.4 scene is introduced.

The owner's latest instruction explicitly requested immediate production publication, with GitHub validation afterward. That overrides the earlier pre-publication gate while preserving honest test reporting. Only the existing `piepe` Worker was deployed, with the existing domain/security configuration and 2.2 rollback version retained. [PR #7](https://github.com/aigars-avotins/piepe/pull/7) is merged. The manual `validation: production` mode remains available for future smoke-only checks; this release uses `validation: release` with `production_smoke: true` to complete both full suites and both live locales in one run.
