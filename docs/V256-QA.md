## Payload / local performance

[Asset comparison](qa/v256/asset-comparison.json): all four MP4s are byte-identical (30,320,610 bytes total); the shared stylesheet is identical (48,637 bytes). Home JavaScript grows from 399,843 to 400,146 bytes, **+74 gzip bytes**. The article prose stays outside that bundle. Each new HTML document is about 11KB, with 3,183 bytes of scoped CSS and shared fonts/styles; neither article requests JavaScript, video or audio. No new runtime dependency or large production asset.

[All samples/method](qa/v256/performance.json): three cold contexts per phase/locale, alternating order, 390×844 DPR1, 4× CPU throttle, real local Worker media preview, unthrottled local network. Articles: median LCP **256ms LV / 260ms EN**, CLS **0**. Home CLS is unchanged (LV 0.001355 / EN 0.002324); sampled locale-switch durations do not increase (maximum LV 184→176ms, EN 192→160ms). These are local samples, not Lighthouse, field Core Web Vitals, INP certification or physical-device timings.

The first three home pairs gave late LCP medians LV 8716→8756ms and EN 7632→8732ms. The larger EN difference warranted [two additional local alternating pairs with LCP element capture](qa/v256/performance-followup.json): both versions' final candidate is the existing animated `.hero-deck.title-enter`, medians **8894→8868ms**. This shows the original sample's sensitivity to the late text reveal, rather than evidence of a consistent loading regression. The small sample cannot certify field equivalence; the inherited cinematic late-LCP behavior remains. No video, brightness, reveal timing or camera code was changed to improve this metric.
