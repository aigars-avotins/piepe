Issue [#20](https://github.com/aigars-avotins/piepe/issues/20); baseline `58301afafec352cad1bead370eab3f3f7ca3a53e`, published 2.5.5. Audit and implementation: 2026-11-06 (Europe/Riga). The owner's current task explicitly authorizes production deployment after validation, superseding the issue's earlier PR-only instruction.

## Audit: already correct

Both production homepages returned 200 with factual, prerendered LV/EN text, localized titles/descriptions, self-canonicals, reciprocal hreflang, one connected WebPage/WebSite JSON-LD document, social metadata and contextual image alternatives. The two-entry sitemap and robots.txt were correct for those two existing pages. Existing security headers/CSP, media byte ranges, 404 handling and cinematic architecture did not need replacement.

The missing capability was a directly addressable, substantial factual reading in each language. The homepage is an artistic cinematic experience, not a species-identification source. No claim is made that metadata or new pages guarantee indexing, rankings or AI citations.

## Implementation

- `/kas-ir-piepe/` and `/en/what-is-a-bracket-fungus/`: concise answer first, then mycelium/hyphae, growth, pores/spores with exceptions, living/dead wood, ecology and limits of identification. Each has contextual source references and an explicit AI-art disclosure.
- Three verified sources (HTTP 200 on 2026-11-06): [Australian National Botanic Gardens](https://www.anbg.gov.au/fungi/what-is-fungus.html) for fungal structures/nutrition; [UC IPM](https://ipm.ucanr.edu/home-and-landscape/wood-decay-fungi-in-landscape-trees/) for wood decay, perennial/annual fruiting bodies, underside variations and tree assessment; [Woodland Trust](https://www.woodlandtrust.org.uk/blog/bracket-fungi-identification/) for bracket diversity/observation. Regional examples are not presented as Latvian species records. No species is inferred from artistic imagery.
- The existing prerender build emits complete standalone article documents. There is no `#root`, `boot.js`, cinema module, video or audio on them: homepage hydration cannot replace their content. Native links preserve the matching language/article and return to the cinematic homepage.
- Unique titles/descriptions/H1, self-canonicals, reciprocal article hreflang and x-default, Open Graph/Twitter. One truthful WebPage with `about: Thing` and the existing WebSite identity; no invented authorship, organization, dates, ratings, FAQ or video metadata. Sitemap now contains exactly four URLs in two reciprocal pairs.
- One restrained real HTML link in the existing homepage facts section. No new runtime dependencies, media or Cloudflare settings. Existing global CSS is unchanged; article CSS is scoped and content-hashed. New JSON-LD hashes extend the existing CSP allowlist without weakening directives.

Read the requested technical/content/hreflang/schema/GEO reference skills from `AgriciDaniel/claude-seo` at `6be93f45064ffbadced572b5d5c95f55fd263af0`, cloned outside the project. No third-party installers or Claude commands ran. Google's official AI features/optimization guidance takes precedence over speculative GEO advice. The [owner Search Console checklist](V256-SEARCH-CONSOLE.md) covers account-only URL inspection, sitemap, Search generative AI controls and Generative AI performance; no account settings were changed.
